# Remotions 视频制作流程与补全计划

适用范围：中文口播、科普和教程。主制作路线为 Remotion，可组合真实录屏、照片、插图、二维或三维场景。画幅按每期需求确定；不自动把横屏裁成竖屏。

本手册依据 2026-10-23 的本地工程整理：已有 9 类、42 个公开动效组件和 `examples/dp-intro/` 教程示例。下面标为“待补”的内容是建设计划，不能视为已具备的功能。

## 一、每期执行顺序

流程：需求与事实 → 参考拆解 → 口播与分镜 → 视觉方向和方案确认 → 素材收集与审查 → 配音和实际时间 → 代表片段 → 全片制作 → 审片与导出 → 归档与复用。

默认先用 Studio 审看可编辑预览。导出、部署、公开发布分别按当期需求执行；提交代码和推送分支不等于发布视频。

| 阶段 | 我负责的工作与交付物 | 你主要决定的事情 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 1. 需求与事实 | 明确受众已有知识、一个学习目标、内容边界；整理可核验的事实和来源 | 给谁看、讲什么、看完应理解或能做什么、画幅和交付形式 | 核心目标与事实依据清楚；不把 AI 生成的画面当成真实操作证据 |
| 2. 参考拆解 | 实际看参考，记录片段时间、关键画面、构图、运动、转场与可复用部分 | 标出喜欢的具体片段，以及不喜欢的效果 | 得到具体的表现要求；仅有链接或“高级一点”不足以指导制作 |
| 3. 口播与分镜 | 写完整口播稿；逐镜写清对象、动作、原因、结果、衔接和所需素材 | 检查是否好懂、信息是否正确、是否符合预期节奏 | 每镜都有目的，重要动词在画面中确实发生；预计时长明确标为估算 |
| 4. 视觉方向与方案确认 | 给出字体、配色、素材质感、构图和运动规则，以及 3 个关键画面的设计说明或已有参考 | 确认完整方案与稿件，选定风格和声音方向 | 记录真实确认；此时不合成配音、不制作占位动画。需要新插图的关键画面，在确认后生成并审看 |
| 5. 素材准备与审查 | 搜集、绘制或生成本期素材；登记来源、使用范围、透明通道、尺寸与分层；审看实际画面 | 判断主体形象和素材质感是否合适；必要时提供只有你掌握的事实或操作记录 | 本制作范围内所有必需输入齐全且审查通过；代码绘制所需的事实、数据和视觉规范也要审查，TSX 不属于前置素材 |
| 6. 配音与实际时间 | 先试听短音色；选定后合成或接收正式配音，检查读音；生成实际字幕时间，调整分镜时间 | 判断语气、音色、速度和停顿是否合适 | 配音可用，字幕与音频实际时长对应；不把字数估时当成字幕时间 |
| 7. 代表片段 | 做 15～30 秒完整片段，包含正式素材、主要运动、衔接、配音和字幕；在 Studio 中播放 | 判断画面、动作和节奏是否达到标准 | 你认可这段的创意表现。检查通过和审美认可分别记录；未达到时只修这一段 |
| 8. 全片制作 | 依分镜搭建独立镜头，复用合适组件；逐镜检查，完成声音与衔接 | 只审新增镜头、关键变化和整片节奏 | 全片没有未处理的素材、内容或同步问题；视觉方向或核心文案改变时重新确认受影响方案 |
| 9. 审片与交付 | 检查讲解逻辑、画面、声音和技术；按需求导出 MP4、字幕、封面及可编辑工程 | 审核最终观看体验；决定是否发布 | 实际播放成片，检查首中末、转场、字幕和音画同步；关键帧不能替代动态审片 |
| 10. 归档与复用 | 保存来源、工程、素材、音轨、字幕、版本和验收记录；把成功镜头提炼入库 | 决定哪些镜头值得长期保留 | 另一份内容可替换文字、图片或数据使用；原视频仍能按原版本重现 |

如果需要先探索风格，可把代表片段设为一个独立的小任务，单独确认它的完整方案和必需输入；片段被认可后再规划全片。不要拿尚未确定的整片反复合成和渲染。

可以直接复制使用：[每期需求、分镜和素材表](templates/VIDEO-BRIEF.md)。

## 二、从参考片中应当提炼什么

参考：[言说新事的 Remotion 实操教程](https://www.douyin.com/video/7697646551179381498)。已在 Codex 浏览器播放并重点查看下列章节；这里不是全片逐秒拆解。

| 参考片段 | 观察到的表现 | 对本库的建设启发 |
| --- | --- | --- |
| 约 7:24，音符案例 | 有透视与光影的乐谱空间，搭配示例视频和制作过程截图 | 需要空间场景、素材、灯光和相机设计；是否引入三维要由具体镜头决定 |
| 约 11:20～12:00，图片素材 | 人物剪贴、建筑、年份与时间线组合 | 先准备合适的视觉素材，建立分层剪贴与时间线镜头 |
| 12:11 起，手绘 | 对比简单线稿和复杂人物场景的绘制方式 | 简单线稿适合路径绘制，复杂画稿可采用设计好的局部显现；显现不等于人物真实活动 |
| 14:43 起，地图 | 地图、路线、照片卡片、地名组合 | 地图和数据是独立输入，路线与标注作为镜头编排；按题材再接入 |

保留参考中具体的构图、运动、质感和镜头关系。参考视频中的图片与源码不会因记录了链接而自动成为本库可分发素材。

## 四、需要补全的东西与先后顺序

### P0：下一期制作前补齐

| 缺口 | 最小可用交付物 | 完成标准 |
| --- | --- | --- |
| 可执行的需求与参考记录 | 本手册和填写后的每期表；2～3 个相关参考片段，带时间点和观察 | 能清楚说明要借鉴的构图、质感、动作与衔接 |
| 第一套视觉规范 | 1 套字体层级、主辅色、背景/材质、阴影、字幕安全区和运动规则；3 张关键画面 | 单帧已经清晰、协调；不同镜头能看出属于同一支视频 |
| 本期素材清单与来源 | 素材表、独立素材编号、本地文件和来源/使用范围记录 | 主体清楚、风格统一；需要分层时分层，需要透明时有真实 alpha，所有引用可追溯 |
| 一个合格的代表镜头 | 15～30 秒，素材、动作、声音和转场完整 | 你认可观看效果；随后替换一次文案或图片仍能正常使用 |
| 明确的声音选择 | 同一段短稿的可选音色试听，记录选择与读音规则 | 专有名词、数字、停顿和情绪合适；本机音色不自动作为正式成片默认 |

### P1：首批镜头被认可后逐步补齐

| 建设项 | 首批范围 | 完成标准 |
| --- | --- | --- |
| 完整镜头模板 | 优先 3 个：截图/录屏讲解、分层剪贴时间线、流程与因果演示；再扩至 5 个 | 每个模板有自己的构图、内部变化、进出场、默认演示和参数说明 |
| 一致的镜头参数约定 | 内容、素材、尺寸、入场/停留/退出、重点时刻、相机/裁切、主题等按需参数化 | Studio 或配置中可调整常用参数，保存后可复现；不要求改写全部旧组件 |
| 按用途检索 | 增加口播/科普/教程标签、素材需求、支持画幅、推荐时长、完成/循环模式 | 从制作目的能找到合适镜头，并能看到真正的动态演示 |
| 风格与素材版本管理 | 区分本库可分发素材、本期素材和仅供参考内容；保存版本与审核状态 | 换题材可以复用适合的素材，旧片不会因素材被覆盖而改变 |
| 声音与成片验收 | 音效/BGM 的本地素材和来源；建立全片试听、手机大小阅读、导出检查记录 | 旁白清楚，音效服务动作；导出的成片实际播放通过 |

### P2：有具体需求再增加

三维场景、地图 API、人物骨骼或动作序列、复杂遮罩、批量渲染和竖屏重排，都按真实题材引入。先验证一个镜头，再决定是否沉淀成公共能力；无需在下一期开始前把这些全部做完。

## 五、第一套视觉规范怎么写

先统一一套适合中文讲解的风格，并用实际画面确认，不同时扩建多个风格库。字体应为可用的本地或随项目正确加载的字体。

- 画面：主背景、主体材质、前后景关系、裁切方式、常用留白。
- 字体：标题、正文、注释、字幕、数字/代码的字体与层级；最终以目标观看尺寸是否可读为准。
- 颜色：主色、强调色、辅助色和语义含义；同一对象跨镜保持含义一致。
- 运动：入场、停留、强调、退场、相机推进的适用规则；定义关键姿态、路径、接触与反馈，不把所有变化统一成淡入。
- 字幕：固定安全区、每行长度、断句规则、背景与对比度；重点内容和字幕不互相遮挡。
- 避免项：挤满说明文字、无目的缩放或粒子、每镜同一布局、不同素材风格混用、讲解还未发生就提前显示答案。

## 六、建议的首批镜头

| 顺序 | 镜头 | 可复用内容 | 首次验收重点 |
| --- | --- | --- | --- |
| 1 | 截图/录屏讲解 | 主画面、局部放大、遮罩、高亮、操作步骤和标注 | 小字可读、重点明确；录屏为真实操作，放大与裁切准确 |
| 2 | 分层剪贴时间线 | 人物/物件、场景、年份、关系线与前后景移动 | 素材质感统一、边缘干净、空间层次和衔接自然 |
| 3 | 流程与因果演示 | 对象、路径、事件、状态改变、结果反馈 | 动作解释概念，观众能看到原因如何导致结果 |
| 4 | 数据比较与结论 | 图表、关键数字、差异提示和结论 | 数据准确、重点易读、动画不扭曲数据含义 |
| 5 | 插图局部显现与镜头移动 | 完整插图、显现顺序、焦点与镜头路径 | 图先好看，显现顺序跟随讲解；无意裁切和空白不暴露 |

前三个是优先建设顺序，不是要求每期必须全部出现。全片按讲解内容选择，避免为了使用模板而改变事实或强塞镜头。

## 七、每期文件组织建议

以下是待采用的组织约定，不表示这些目录和工具已经实现。现有 DP 示例无需为文档进行搬迁。

```text
episodes/<episode-id>/
  brief.md                 # 需求、受众、唯一目标和交付形式
  references.md            # 链接、时间点、关键帧和观察
  sources.md               # 事实来源及需要核验的断言
  plan.md                  # 全片视觉与逐镜方案
  script.txt               # 确认后的完整口播
  episode.json             # 画幅、视觉、声音方向等元数据
  composition.json         # 镜头类型、意图和时间线
  production.json          # 真实确认、素材审查与阶段状态
  assets/
    manifest.json          # 采用后记录下方素材表对应字段
    originals/             # 原始文件保留版本
    approved/              # 审查通过的本期素材
  public/                  # 实际供 Remotion 使用的本地资源
  audio/                   # 原始配音、BGM、音效，分轨保存
  captions/                # 实际字幕与时间标注
  src/scenes/              # 每镜独立实现
  review/                  # 代表片段反馈与逐项处理记录
  outputs/                 # 需要时保存最终成片与交付物
```

大体积原始素材和生成缓存不默认提交 Git；代码、登记表、必要小型资源与版本关联应可追踪。正式交付包应包含实际播放所需文件，不能只留本机绝对路径。

## 八、给后续每次制作的执行要求

1. 使用每期表先整理需求、事实、参考与分镜；你只需提供主题、受众和参考偏好，其余可由我起草。
2. 我负责提出画面、准备可取得的素材和完成实现；只有你掌握的信息或真实操作材料才需要你提供。
3. 确认记录必须来自你对具体方案的实际回复，不把已有工程、工具检查或旧样片当成新方案认可。
4. 素材与数据通过审查后再配音和制作；配音后使用实际时间修正镜头与字幕。
5. 先审代表片段，明确记录创意反馈，达到标准后制作全片。
6. 分别记录事实正确、动态视觉效果、声音和技术结果；“测试全通过”不能替代“视频好看”。
7. 项目改动在开发分支验证并推送，继续遵守“改完就推送”的约定；合并、部署和公开发布单独按你的指令执行。
8. 从被认可的作品提取镜头模板，完善素材库；不把未经认可的样片自动标成成熟模板。

## 九、下一步的最小任务

先做“第一套视觉规范 + 一个完整代表镜头”。可从 DP 的“只看最后一步”选一段，重新设计主体、构图、动作和镜头衔接，或换成截图/录屏讲解题材。先提交具体方案和关键画面方向供选择，再准备素材和制作。这个阶段的目标是明确你认可的质量标准，尚不重做整期或扩建全部模板。
