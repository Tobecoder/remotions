# 组件边界约定

本约定用于动画组件设计、素材入库、组件拆分、组合迁移及范例补充。首要判断标准是：**完整效果是否方便复用**。使用者或 AI 应能找到已有的完整效果，替换所需内容并沿用经过确认的布局和节奏。

## 完整效果优先

- 拆分服务于完整效果的复用和维护；多个镜头确实共用动作，或拆分有助于稳定替换内容时再抽离，不以组件数量或粒度作为目标。
- 动作组件提供基础能力，完整范例提供可选用的镜头。固定业务组合可以留在案例工程，同时作为范例保留可浏览入口，不因退出公开 API 而失去预览和使用指引。
- 范例与原案例复用同一份组合实现，列明关联动作、用途、可替换内容、需要保留的布局/方向/相对节奏、代码入口及验收状态。新的范例状态需由用户确认，测试或构建通过不等于视觉验收。
- 按已拆分组件逐项补充对应范例；完成当前项的入口、预览和替换说明后，再处理下一项。AI 制片时先选择适用的完整范例，沿用其效果，再填入内容；新布局或超出说明范围的内容需要重新验收。

## 职责归属

| 位置 | 职责 |
| --- | --- |
| `packages/animations/src/` | 提供可独立调用的动作，例如文档窗口、区域高亮、标题收拢和单条进度。 |
| `apps/catalog/src/` | 为独立组件提供分类、预览和用法，并关联完整范例的预览与说明入口。 |
| `examples/` | 保存组合实现、镜头时间和文案配置，支撑具体成片及完整范例；范例入口引用原有组合。 |

## 入库条件

- 动作可以独立调用，调用方可以替换所需文案、素材或数值。
- 动作进度、开始时刻或播放时间由调用方控制，能够适应另一条视频的节奏。
- 位置、尺寸、颜色和内容按实际复用需求提供参数或插槽，保持接口简洁。
- 特定讲解顺序、跨多个动作的固定时间线、业务结论和场景文案归案例工程。
- 一个动作内部可以组合多个元素；按它是否能独立复用判断归属，避免只因内部元素较多就继续拆分。

## 素材目录与公开 API

- 素材目录的动作项与组件包公开入口登记符合入库条件的组件，组件名称、分类、用法和导出保持一致。关联的完整范例单独标记，不计为新增公开动作组件。
- 固定业务组合及其专属类型留在案例工程，退出独立动作列表及 `packages/animations/src/index.ts`、`packages/animations/src/reference-opening/index.ts` 两处入口；通过完整范例保留选用入口，不通过库入口提供兼容别名。
- 组件库和素材站的动作实现不反向依赖案例组合代码。案例从组件库调用独立动作；素材站可读取范例元数据并展示由案例代码生成的预览产物。

当前示例中的 `ScriptDocumentGuide`、`ProgressRace`、`SpotlightSequence`、`DocumentFocusGallery`、`SectionCollapse`、`SceneThumbnail`、`PreparationCards` 位于 `examples/reference-opening/compositions/`，分别编排文档讲解、快慢进度对比、卡片强调镜头、五卡文档聚焦、小节摘要收束、章节缩略卡及四卡素材准备；它们不作为独立动作登记或导出，可通过完整范例关联到对应动作。

## 修改与迁移

1. 先检查已有组件和调用方，确定要复用的独立动作以及属于案例的编排。
2. 相同动作复用素材组件的实现；案例负责传入内容与时间，避免另写一套动作导致效果漂移。
3. 拆分或迁移时保留已确认的动画方向、最终位置和节奏；视觉调整按当次用户要求执行。
4. 组合退出动作目录时，一并迁移案例引用，清理运行时/类型导出及旧用法；保留组合实现，并为对应动作关联完整预览、替换说明和代码入口。
5. 按改动范围验证独立调用、目录与导出一致性、原案例运行及动作衔接；范例需能被找到、完整播放并按说明替换内容。构建和数值检查与视觉验收分别说明；仅文档改动检查内容和引用即可。

现有组件按实际复用需求逐项评估，本约定不授权批量删除其他组件或改写已确认的成片。
